# tuigram: полный аудит функционала и UX-позиционирование TDUI

**Версия tuigram:** `tuigram-cli 1.8.0` (октябрь 2026)
**Дата аудита:** 31.10.2026
**Источники:** README, исходный код (git clone), `docs/` репозитория
**Характер аудита:** статический, по README и исходникам. Живой прогон с реальным аккаунтом не выполнялся.

**Легенда статусов:**

| Статус | Значение |
|---|---|
| ✅ | Есть и работает как заявлено |
| ⚠️ | Есть, но с ограничениями |
| ❌ | Нет |
| ❓ | Не заявлено, в коде не найдено или требует живой проверки |

---

## 1. Краткий вывод

1. **tuigram — сильный vim-first TUI-клиент.** Для текстовой переписки, медиа-просмотра и секретных чатов он закрывает почти всё, что нужно ежедневному пользователю.
2. **Его главная сила — не количество фич, а UX-детали:** фокус-зависимые read receipts, черновики, повтор failed-сообщений, подтверждения опасных действий, понятные подсказки в статус-баре, `?`-help и завершение команд.
3. **Главная слабость — он сделан для vim-пользователя, а не для «обычного человека».** Нет мыши, нет простого режима, нет локализации, клавиши не перенастраиваются, а кривая обучения высокая.
4. **Вторая слабость — управление аккаунтом.** Нельзя редактировать профиль, добавлять контакты, создавать группы/каналы, управлять устройствами, приватностью, блокировками и сессиями. Как замена официальному клиенту tuigram неполон.
5. **Третья слабость — приватность at rest.** TDLib запускается с пустым `database_encryption_key`: локальная база не шифруется, локального пароля нет. Для privacy-conscious пользователя это серьёзный минус.
6. **Четвёртая слабость — зависимость от терминала.** Уведомления и картинки работают по-разному в разных терминалах; на Windows Terminal изображения — только блочный fallback, а для уведомлений нужно включать `allowOSC777`.
7. **Функциональные пробелы:** нет глобального поиска по сообщениям, мультивыделения, ручных «прочитано/непрочитано», длительности mute, записи голосовых, видео-сообщений, GIF-поиска, отложенных сообщений, перевода, stories, звонков, комментариев и управления папками/топиками.
8. **Окно для TDUI:** не пытаться обогнать tuigram по числу фич. Выигрывать надо на **user-friendliness для более широкой аудитории**: русский язык, простой режим + vim, мышь, нативные уведомления с приватностью, passcode/шифрование, мультиаккаунт, глобальный поиск и доступность.

**Оценка tuigram по 5-балльной шкале:**

| Роль | Оценка | Почему |
|---|---:|---|
| Vim-first TUI для текста и медиа | 4/5 | Богатый функционал, хорошие UX-детали, стабильная архитектура |
| Замена официальному клиенту | 2.5/5 | Нет управления аккаунтом, контактами, группами, приватностью, устройствами |
| Массовый user-friendly продукт | 3/5 | Высокий порог входа: vim, английский, нет мыши и локализации |
| Приватность и безопасность | 3/5 | Отличные focus-aware receipts, но нет шифрования БД, passcode и управления устройствами |

## 2. Метод и ограничения

- Прочитан README (33 КБ) и исходный код `src/` (Rust, ~60 модулей, включая собственный Opus-декодер).
- Проверены ключевые модули: `app.rs`, `tg.rs`, `chats.rs`, `messages.rs`, `search.rs`, `secret.rs`, `topics.rs`, `images.rs`, `notify.rs`, `settings.rs`, `attach.rs`, `voice.rs`.
- «Не заявлено» не всегда означает «точно нет»: часть возможностей может приходить из TDLib и не быть выставлена в UI. Такие места помечены ❓.
- Живой прогон не выполнялся: в окружении не установлен Rust-тулчейн, а для реального аккаунта нужен тестовый номер.
- Оценки полноты — экспертные, для приоритизации, а не точные метрики.

## 6. UX-анализ

### 6.1 Что tuigram делает хорошо

1. **Приватность по умолчанию.** Read receipts и online уходят только когда окно и чат в фокусе, а сообщение реально на экране. Это лучше, чем у многих GUI-клиентов.
2. **Подтверждения с контекстом.** Опасные действия (выход, удаление, переход по замаскированной ссылке, запуск файла, прокси) спрашивают и показывают реальный хост/сервер. Есть grace-период, чтобы случайный Enter не нажал «да».
3. **Черновики и retry.** Черновик синхронизируется с Telegram, а failed-сообщение можно отправить повторно одним Enter.
4. **Обнаруживаемость для клавиатурного пользователя.** Статус-бар подсказывает доступные клавиши, `?` открывает полный help, `:`-команды дополняются по Tab.
5. **Мощный поиск в чате.** Фильтры `from:`, `has:`, `before:`, `after:` + подсветка + `n/N` — это уровень, которого нет у многих TUI.
6. **Техническая полировка.** Определение протокола картинок, tmux passthrough, бюджеты памяти, очистка kitty-изображений, обработка смены DPI.
7. **Секретные чаты.** Полноценные E2E-чаты с таймерами и визуальной сверкой ключа — редкость для TUI.
8. **Нет телеметрии.** Пользователь платит только Telegram, никаких промежуточных серверов.

### 6.2 Где пользователь спотыкается

#### Сценарий 1. Первый запуск

- Скачал релиз → QR/телефон → чаты. Хорошо.
- Собирает из исходников → нужен `api_id`/`api_hash`, иначе логин не начнётся.
- Интерфейс на английском, управление vim-модальное. Новичок не понимает, что нажимать.
- Обучающего тура нет; `?` нужно ещё найти.

**Вывод:** порог входа высокий для не-vim пользователя.

#### Сценарий 2. «Я просто хочу кликнуть чат»

- Мыши нет.
- Нужно знать `j/k`, `Enter`, `i`, `Esc`.
- Вставка из буфера и drag-and-drop есть, но это не заменяет клики.

**Вывод:** для массового пользователя это главный барьер.

#### Сценарий 3. «Я хочу найти сообщение по всем чатам»

- В чате поиск отличный.
- В списке чатов `/` фильтрует только названия.
- Глобального поиска по сообщениям нет.

**Вывод:** заметный функциональный пробел.

#### Сценарий 4. «У меня два аккаунта»

- Один TDLib-клиент, один аккаунт.
- Смена — только через `:logout` и повторный вход.
- Параллельной работы нет.

**Вывод:** мультиаккаунт — сильный дифференциатор для TDUI.

#### Сценарий 5. «Я не хочу, чтобы текст сообщений светился в уведомлениях»

- Настройки скрытия текста нет.
- Тело уведомления содержит текст (кроме секретных чатов).
- На Linux/macOS это может быть видно в lock screen/notification center.

**Вывод:** privacy-баг для чувствительных пользователей.

#### Сценарий 6. «Ноутбук украли»

- TDLib-база не шифруется, passcode нет.
- Сессия = полный доступ к аккаунту.
- Управления устройствами в приложении нет.

**Вывод:** серьёзный риск; passcode/шифрование — один из главных дифференциаторов.

#### Сценарий 7. «Я на Windows Terminal»

- Картинки — halfblock, не полноценные.
- Уведомления — только после `allowOSC777`, иначе bell.
- Для реальных картинок нужен WezTerm/kitty/Ghostty.

**Вывод:** Windows-опыт вторичен; для TDUI это возможность.

#### Сценарий 8. «Мне нужно отправить голосовое/видео»

- Голосовые можно слушать, но не записывать.
- Видео уходит файлом, без плеера и превью.
- GIF-поиска нет.

**Вывод:** медиа-функционал неполон для повседневного использования.

#### Сценарий 9. «Я хочу быстро обработать пачку сообщений»

- Мультивыделения нет.
- Нельзя разом удалить/переслать несколько сообщений.
- Нельзя вручную отметить чат прочитанным/непрочитанным.
- Mute только навсегда.

**Вывод:** power-user сценарии хромают.

#### Сценарий 10. «Я хочу заменить официальный клиент»

- Нельзя редактировать профиль, добавлять контакты, создавать группы, управлять приватностью, устройствами, блокировками.
- Нет звонков, stories, комментариев, отложенных сообщений, перевода.

**Вывод:** tuigram — отличный второй клиент, но не замена официальному.

## 8. Стратегия TDUI: где выигрывать

### 8.1 Позиционирование

**«Telegram TUI для людей, а не только для vim-гиков».**

tuigram уже занял нишу «vim-first, максимально близко к Telegram». Идти туда же и делать то же самое — проигрыш по времени и по аудитории. TDUI должен выиграть на **комфорте для тех, кто не живёт в vim**:

- понятный первый запуск;
- два режима: Simple (по умолчанию) и Vim (для опытных);
- мышь;
- русский язык;
- уведомления, которые не стыдно показать на lock screen;
- passcode;
- мультиаккаунт;
- глобальный поиск.

### 8.2 Целевые персоны

1. **Терминальный разработчик, не vim-эксперт.** Живёт в терминале, но хочет клики/стрелки и понятные подсказки.
2. **Русскоязычный пользователь.** Английский интерфейс — барьер; русский UI + раскладка = преимущество.
3. **Privacy-conscious пользователь.** Хочет passcode, скрытие текста уведомлений, управление устройствами.
4. **Мультиаккаунт.** Работа/личное, несколько номеров.
5. **Power-user.** Глобальный поиск, batch, кастомные клавиши, command palette.

### 8.3 Дифференциаторы

| Дифференциатор | Почему выигрывает |
|---|---|
| RU/EN + архитектура i18n | tuigram только на английском |
| Simple + Vim + мышь | tuigram только vim и без мыши |
| Passcode + encrypted DB + devices | tuigram не шифрует БД и не даёт passcode |
| Скрытие текста уведомлений | tuigram показывает текст |
| Мультиаккаунт | tuigram — один аккаунт |
| Глобальный поиск | tuigram ищет только в чате |
| Batch-действия и read/unread | tuigram не умеет |
| Нативные уведомления | tuigram зависит от терминала |
| Accessibility | tuigram почти не думает об этом |
| Auto-outbox | tuigram требует ручного retry |

### 8.4 Чем не конкурировать в v1

- Звонки.
- Stories.
- Платежи и mini apps.
- Полное администрирование групп/каналов.
- Feature parity с официальным клиентом.

Это ловушка: tuigram уже потратил месяцы на глубину, а мы можем выиграть наUX-слое, а не на количестве кнопок.

## 11. UX-метрики, по которым сравнивать

| Метрика | Цель TDUI | Как мерить |
|---|---|---|
| Time to first message (TTFM) | < 2 минут от запуска | Секундомер на новом пользователе |
| Task success без документации | ≥ 90% для 10 базовых задач | Usability-тест |
| Поиск помощи | 1 клавиша (`?`), 2 — command palette | Проверка сценария |
| Поиск сообщения по всем чатам | < 10 секунд | Сценарий |
| Input latency | < 50 мс | Замер рендера |

## Приложение B. Быстрые выводы для продуктовой стратегии

1. **Не копировать tuigram 1:1.** Его ниша — vim-first; наша — user-first.
2. **P0-дифференциаторы:** RU/EN, Simple/Vim + мышь, passcode/encryption, notification privacy, onboarding.
3. **P1-дифференциаторы:** multi-account, global search, batch, voice recording, native notifications, custom keys.
4. **P2:** stories, calls, comments, translation, scheduled, inline bots, payments, mini apps.
5. **Главный принцип:** каждое решение проверять вопросом «станет ли пользователю комфортнее?», а не «есть ли это у tuigram?».
